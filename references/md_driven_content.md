# MD 结构驱动 · 内容密度准则（组会PPT）

> 适用：用户给了一篇有逻辑分区的 Markdown（论文深读笔记 / 文献解读），要求做组会PPT。
> 目标：deck 必须**忠实镜像 md 的分区结构**，且每页**内容充实**，不能只放 3–4 句泛泛 bullet。

---

## 0. 总原则（先读结构，再定页）

1. **用 md 的标题层级当 deck 骨架**，不要拍脑袋定页数。
   - `##` = 一个大章（对应一个分区 / 一组页）
   - `###` = 子节（对应一页或一个卡片块）
2. 用户若说"背景纯白"= 内容区白底 + 浙大蓝装饰；**不是**全页素白无美化。
3. 若 md 字数多但有逻辑分区，优先把分区"显式化"（Agenda + 分隔页），而非压成几页薄 slide。

---

## 1. 必加：汇报路线 / Agenda 页

- 把 md 所有 `##` 一级分区列成**编号清单**（如 8 项），每项一句话说明。
- 让听众一眼看到"这篇笔记是沿哪几个分区组织的"——这是分区可见性的第一道保障。
- 通常紧跟封面之后（第 2 页）。

## 2. 必加：章节分隔页（Divider / Chapter）

- 在大的 `##` 分区之间插入分隔页，显式标注"第几部分 · 标题 · 一句话描述"。
- **白底约束下**的做法（尊重"背景纯白"）：白底 + 大号蓝色章节号（半透明/浅蓝）+ 蓝色标题 + 橙色竖条 + 右侧蓝色几何装饰线。
- 也可用模板自带全蓝 chapter 页（zju_blue `02_chapter.svg`），但全蓝页会违反"背景纯白"，仅当用户明确要强分隔时才用。

## 3. 结果图小节：固定"四段式"总结（最关键）

对 md 中带 `![[figN]]` 的每个结果小节，**不要只放图 + 3 句 bullet**。按 md 本来的叙述结构拆成四段：

| 段 | 内容来源 | 放哪 |
|----|----------|------|
| **实验目的** | md 的"实验目的：" | 左栏顶部 |
| **图意拆解** | md 的 Panel A / B / C / D 逐块要点 | 左栏中部（用 ▸ 列出） |
| **核心发现** | md 的"核心发现：" | **页眉下的 key-message 条**（蓝底/浅蓝条，最显眼） |
| **逻辑衔接** | md 的"逻辑衔接："（为什么做这步、如何连上下一步） | 左栏底部（橙色 tag 强调） |

- 图放右栏，`preserveAspectRatio="xMidYMid meet"` 高度优先，蓝色描边图框 + 浅蓝投影。
- 这样每一张结果页都完整复现 md 小节的"目的→拆解→发现→衔接"逻辑链，内容密度自然够。

## 4. 背景类小节：子分区用卡片网格

- 若背景有 `### 1.1–1.4` 子分区，**用 2×2 卡片网格逐一呈现**，不要合并成一段。
- 每张卡片：蓝/深色标题条 + 正文；不要均匀卡片网格（品味守卫 🔴），可 2×2 不等高或左蓝边卡片。

## 5. 方法类小节：材料表 + 方法步骤链

- `### 4.1 材料` → 一张**表格**（类别 | 内容）。
- `### 4.2 方法` → 把 N 个 protocol 拆成**编号卡片网格**（如 7 步链），每卡一行 essence + 左侧蓝竖条。
- 不要整段粘贴；用户要的是"可复现要点"的精炼结构。

## 6. 浙大蓝模板（templates/layouts/zju_blue）

直接用 skill 内置的 `zju_blue` 模板系统，不要手搓配色：

| 角色 | 色值 |
|------|------|
| 主蓝（页眉带/标题/表头） | `#003F88` |
| 强调蓝（线/次级条/分隔线） | `#2B6CB0` |
| 橙色点缀（左竖条/分隔圆点） | `#ED7D31` |
| 浅蓝（key-message 条/卡片底） | `#EBF2FA` |
| 灰线 / 正文灰 | `#D0D7E0` / `#545458` |

**内容页结构**：顶部 70px 蓝色页眉带（左橙竖条 + 白色"章节号 标题"）→ 下方 50px 浅蓝 key-message 条（放核心发现）→ 白底内容区 → 页脚浅蓝线 + 页码。
**封面**：白底 + 顶部蓝色带 + 居中蓝标题 + 橙色分隔圆点 + 底部浅蓝带。

---

## 7. 反 slop 提醒

- 用户明确反对"内容单薄"：密度要够，分区要显式（Agenda + 分隔页 + 四段式）。
- 但单页仍要可读：密度高时用**卡片/表格/双栏/时间线**，不要堆大段文字；单页文字块超过 ~6 行考虑拆页。
- 图必须落在 md 链接位置、按原比例；背景纯白、装饰用浙大蓝。

---

## 8. 排版与美学：字号 + 段落级文本框（svg_to_pptx 的 `data-wrap-w`）

> 用户明确反对两点：**正文太小**（难读、不美观）和 **"一行 = 一个文本框"**（一段话被拆成几十个不可编辑的小框）。

### 8.1 字号体系（在 1280×720 画布上，1px = 0.75pt）

| 角色 | px | ≈ pt | 说明 |
|------|----|------|------|
| 内容页标题（页眉带） | 30 | 22.5 | 章/节标题 |
| 关键发现条（key bar） | 18 | 13.5 | 页眉下浅蓝条 |
| **正文段落** | **18–20** | **13.5–15** | 结果页用 20px 最显眼；**严禁 < 14px 的正文**（≈10.5pt，太小） |
| 卡片 / 节点标题 | 17–18 | ~13 | 与正文拉开层级即可 |
| 区块 tag 标签 | 15 | 11.25 | 实验目的 / 图意拆解 / 逻辑衔接（短标签，可小） |
| 讨论 / 批判 bullet | 19 | 14.25 | 比正文略大，强调论点 |
| 页脚 / 注 | 13 | ~10 | 仅元信息，允许小 |

- 16:9 投影场景正文至少 14pt；**默认取 18–20px 更稳妥**。
- 字号一大，单页能放的文字行数变少 → 用 §1–§5 的卡片 / 表格 / 双栏 / 分隔页来承载密度，而不是缩小字号硬塞。

### 8.2 段落级文本框（核心修复）

`svg_to_pptx` 的 `convert_text` 默认把**每个 `<text>` 当成一个单行自动缩放文本框**。若作者为每段文字的每个视觉行都发一个 `<text>`，结果就是"一段话 = 几十个小框"，编辑灾难。

**正确做法**：用转换器支持的段落包裹属性——

- **一个逻辑段落 = 一个 `<text data-wrap-w="W">`**（W 为该段可用宽度，px）。转换器会生成**单个可编辑文本框**，PowerPoint 按 W 自动换行（`wrap="square"`）。
- 段落内要多行（如 Panel A–D），用**子 `<tspan>`（不带 x/y/dy）**表示换行；转换器保留为同一文本框内的 `<a:br/>` 行断，**不会**拆成多个框。
  （注意：带 x/y/非零 dy 的 tspan 会被 flattener 提升成独立 `<text>`，所以行标记务必"无定位属性"。）
- 短标签（tag / 页眉 / 页脚）仍可用普通单行 `<text>`（它们本就是一行）。

生成器里对应两个helper：`para_box(text, x, y, w, fs, …)`（单段落）→ 一个框；`para_box_multi([line1, line2, …], x, y, w, fs, …)`（多行同框）→ 一个框 + `<a:br/>`。两者都按 `est_lines()`（与转换器 `_estimate_wrapped_lines` 一致的 CJK 宽度估算）预算框高，避免堆叠重叠。

**校验清单**：导出后抽查一张结果页，非空白文本框应为「页眉 + 3 个 tag + 3 个段落框 + 页脚」≈ 10–12 个，而不是 30+ 个；正文 run 的 `font.size` 应 ≥ 13.5pt。
